# 淬火版本发布

以当前源码、真实已分发包和本次候选产物为依据。历史对话和旧发布脚本提供线索，不能代替本次产物验收。任务只要求“准备”时，停在候选产物及交接单；不自行上传、替换线上清单、打开门禁或删除远程资产。

## 先读取

- 每次发布：完整阅读 [准备与验收清单](references/preparation.md)，按其中的输入表建立本次记录。
- 生成产物或交接网站：阅读 [协议、代码与工具位置](references/contracts-and-code.md) 的对应章节，核对源码中的实际参数、路径和协议。
- 涉及跨版本更新：阅读仓库 `wiki/file-sync-updates.md`；涉及已分发 3.5／3.51：同时阅读 `wiki/3.51-client-bugfix-verification.md` 中的发布验证、基线调查和未发布改动。
- 涉及 MOD 后续资源更新：阅读 `wiki/mod-zip-updates.md`。2026-10-09 用户决定 MOD 改为逐资源版本普通 ZIP，客户端保留已验收的按文件差异更新；旧同协议描述仅作为兼容历史。
- 实现代码修改时，另遵循仓库现有项目指引；本 skill 不授权顺带重构客户端。

本文及 references 中的代码路径均相对仓库根目录，不能相对当前 skill 目录执行命令。

## 决策顺序

1. 确认用户要准备、上传候选，还是正式发布，以及本次公开版本与内部版本。
2. 保存真正已分发的旧客户端和旧 MOD 官方快照，然后才构建或替换 latest 下载包。
3. 完整包／MOD 的唯一资源事实源是 `D:/Quenching/QM/Latest`。直接扫描它生成候选清单、完整包和补丁；不创建／复用历史 `mod-root`、冻结资源树或资源覆盖层提供新版本内容。客户端 `assets/` 是客户端自身输入，不反向覆盖 Latest。详细入口见 [Latest 唯一源流程](references/latest-source.md)。
4. 按下表准备，不把客户端版本递增误当成 MOD 版本递增。

| 本次范围 | 客户端 | MOD 更新与完整包 |
| --- | --- | --- |
| 仅客户端修改 | Win／Mac 新便携 ZIP；Windows 更新产物及签名清单 | 保持 MOD 版本、sequence、清单和原完整包不变 |
| 仅 MOD 修改 | 保持客户端版本和清单不变 | 从 Latest 生成新资源清单及版本 ZIP；按需要制作首装 A／B |
| 客户端＋MOD 修改 | 同上 | 从 Latest 生成新官方文件清单及更新产物；需要更换首装下载时再制作独立 A／B ZIP |

5. 分清旧 schema 1 兼容引导和新 schema 2 文件同步，分别测试真正使用它们的客户端。旧代码不会因为服务器换了清单而获得新协议支持。
6. 候选上传后验证每个源的实际字节，再用真实旧便携包在隔离目录完成升级、重启和回滚验收。
7. 给用户产物和明确剩余问题，等待其实际游戏测试。只有在获准发布窗口内才协调网站切换；正式开门禁后再次测试无预览绕过的客户端。

## 必须保留的项目约束

- 当前发布主源是 **GitHub Release＋官网清单控制的备用镜像**；两产品分仓库。GitLawb 已因持续失败被用户停用，不作为发布必需项；不是 GitLab。Irys 当前停用，`_irys/` 只是既有私有发布工具目录名。R2 是私有 Worker 最后备用，须实际验收对应传输后才能启用。
- 不提供安装程序；客户端是便携 ZIP。完整包 A／B 是两个可分别解压的普通 ZIP，不能制作需要拼接的 `.001/.002` 分卷。自动更新传输的内部分片是另一回事。
- 内部客户端 `3.5.1` 对应用户口中的 `3.51`，对外可仍显示 `3.5`。新内容要用更高的内部版本；不能重建同一个内部版本并期待已装该版的玩家收到更新。
- 资源版本读取分支 `_patch/keep.que`；没有新标记时，3.4 仅用 `Rbuildings`、`RetroTex`、`RUnits` 三个固定目录识别，各自可以在该分支根或其 `QMoff`。保留 `_retail_`、`_ptr_` 下划线。
- 自动检查在启动约 10 秒后，只读小型索引和版本标记。文件清单用于发布元数据比较，不用于扫描玩家目录猜版本或强制玩家目录 100% 等于标准包。
- 用户确认前不下载／安装。MOD 与客户端共用一个确认弹窗，显示当前和目标版本；同时更新时先资源包，再客户端。
- 不能因新清单里没有某文件就删除玩家文件。开启 MOD 不要求完整包、标记或所有权清单齐全。已明确由客户端管理的当前分支 `ui` 可重置，这不扩展到其他目录。
- 客户端源 `assets/` 一律复制，不移动。发布准备不得反向修改 `assets/quenching` 来适配 QMF，也不默认用客户端 assets 覆盖 Latest。用户明确要求对齐时，先作为资源编辑复制到 Latest 并核对；发布工具仍只读取 Latest。玩家自定义、原导入文件、另一分支和设置必须保留。
- 客户端保持当前／最新官方快照比较，EXE／ASAR 可选差分、失败回退目标单文件；其他变化资源整文件。MOD 改为相邻官方资源版本各一份普通 ZIP，官网签名 schema 3 索引控制连续更新链、源和步数上限（默认 6）。每步独立提交／失败回滚，不强制玩家旧目录符合清单；不再为新 MOD 发布逐文件对象。签名和下载哈希仍验证。
- 不擅自升级 Electron。当前自动更新仅 Windows x64；内核／核心变化走新便携包。macOS 仍手动更换，不给它 Windows 清单。
- `_irys/`、`.env`、上传身份和签名私钥不进入 Git、客户端、ZIP 或公开清单；客户端只带公钥。保留历史资源清单、签名索引、必要补丁／正式 ZIP 和真实旧客户端基线；不要每版保留完整解压资源树。移除旧树前解除发布工具和测试对它的依赖。
- 官网元数据保持 `qm.txzy.net`，旧域兼容另核对；客户端埋点仍用 `https://qm.txzy.net/v1/telemetry/events`，不要因为后端迁移修改客户端 URL。
