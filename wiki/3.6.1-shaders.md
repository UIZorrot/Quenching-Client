# 3.6.1 着色器与 ZIP 资源准备

本轮只准备客户端，保持正在发布的 MOD 3.6、完整包和线上签名索引不变；不自动上传。当前源码包含同事的工作区修改，以及 2026-10-09 官网控制更新 / 独立测试 flag 的修改。内部客户端与首页产品版本为 3.6.1。

## 游戏版本与资源对应

| 首页选择 / 自动检测 | Retail HD / DE | PTR HD / DE |
| --- | --- | --- |
| 3.0（3.0.0.*） | 旧 3.5 的 300 着色器 | 同一套已知兼容 3.0 的 300 着色器 |
| 3.0.1+ | 当前 300 目录中的新版着色器 | 当前 PTR 着色器 |
| 2.x / 1.x | 保留对应历史档位 | 保留对应历史档位 |

当前源码的 `shaders-300-hd/de` 是历史目录名，内容是同事确认在 3.0.1 工作的新版；本轮不重命名或回退这些可编辑目录。新增的 `shaders-300-legacy-hd/de` 只作为旧版 ZIP 内的兼容档位标识。3.0 与 3.0.1+ 都仍使用现代 DNC / Skin / DE 设置，不能误落入 2.x 皮肤表。

已知旧来源：`C:/Users/uizor/Desktop/QMC3.5-Win/QMC3.5-Win/resources/assets/quenching`。只读取该包的 `shaders-300-hd`、`shaders-300-de` 和 `fog_shaders`，不移动 / 修改旧包。旧 fog 单独放在 ZIP 内 `shaders/fog_shaders-legacy/`；3.0 不能被新版亮度 fog 覆盖。

## 压缩与本地展开

- `assets/quenching/shaders.zip`：当前可编辑 shaders 树；149 项，原始 256,344,552 字节，ZIP 18,603,884 字节（首次生成记录，后续资源修改须重建）。
- `assets/quenching/shaders-300-legacy.zip`：已知旧版兼容资源；57 项，原始 73,352,806 字节，ZIP 5,186,242 字节。
- 两者都是标准、独立 ZIP，不是分卷。源码散文件保留，Windows / Mac 便携包排除 `quenching/shaders/` 的重复散文件，只带两个 ZIP。
- 运行时只展开当前 pack 与对应 fog 目录，不把所有档位全量解压到客户端 / C 盘。临时目录位于选中游戏分支旁，用完或失败都会清理。
- 首页切换、启动同步、物体着色器开关、两组后处理开关、Intel/AMD 恢复均从同一档位取源。关闭开关删除游戏内覆盖；重新开启从 ZIP 复制，不混用另一版本 / 分支资源。
- 当前客户端自动更新可直接把变化 ZIP 视为普通整文件更新；无需为每个 `.bls` 上传一个附件。旧客户端升级后留下的散文件不强制删除，新代码优先使用 ZIP，因此不会覆盖新选择。

## 开发与构建

首次导入旧兼容包：

```powershell
node scripts/prepare-shader-bundles.mjs --legacy-source 'C:/Users/uizor/Desktop/QMC3.5-Win/QMC3.5-Win/resources/assets/quenching'
```

以后旧兼容 ZIP 随源码保存，不要求其他开发机具有该桌面目录。修改当前散 shaders 后，`npm run build` 会用 `scripts/prepare-shader-bundles.mjs` 重建新版 ZIP；不会修改散文件或从运行中的游戏目录取源。ZIP 使用固定元数据，相同源内容不会产生无意义的不同字节。缺少旧兼容包时构建明确报错，不静默漏打包。

Windows 的 `electron-builder.yml` 与 Windows 上 Mac 打包器 `scripts/package-mac-app.mjs` 均已加入散 shaders 排除。直接调用底层 webpack / 打包命令前，先运行 shader 准备脚本，避免拿旧 ZIP 当最新版。

## 回归范围

```powershell
npm run test:shader-301 -- 'C:/Users/uizor/Desktop/QMC3.5-Win/QMC3.5-Win/resources/assets/quenching'
node --import tsx scripts/test-fog-shader-override.ts
node --import tsx scripts/test-unit-skin-profile.ts
npm run test:update-channel
npm run test:update-download
npm run test:file-sync
npm run test:i18n
npm run build
```

`test:shader-301` 模拟两个分支实际版本、执行真实 ZIP 选档与复制、核对旧来源的全部对应文件哈希，并覆盖 ZIP-only 资产的 shader 开关和临时目录清理。游戏安装与资源写入均在独立临时目录，版本检测 / 配置 / Electron 接口隔离；没有启动真实游戏。

测试通过证明资源选择和字节来源正确，不代替用户测试魔兽 3.0 / 3.0.1 / PTR 的实际图形效果。Mac 可共用资源逻辑与 ZIP，Windows 上的回归不等于 Mac 实机启动验收。

下一步制作候选便携包和 3.6 → 3.6.1 签名文件同步清单时，必须把保留的镜像放进 `fileSync.githubMirrors`（源码不再自动添加镜像），并使用官网测试端点先验收；旧兼容引导不逐版本重建，也不删除已有玩家仍在使用的 3.5 附件。详见 [官网控制更新方案](website-controlled-updates.md)。
