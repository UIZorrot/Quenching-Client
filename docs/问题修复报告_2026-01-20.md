# 淬火MOD客户端问题修复报告

## 修复日期
2026-01-20

## 修复的问题

### 1. Remote Version 总是拉取不到（显示空白）

#### 问题原因
- 网络请求超时时间太短（10秒）
- 没有重试机制
- 没有备用URL
- 返回空字符串时没有默认值处理

#### 修复方案
**文件**: `src/Main/ipc/version-handlers.ts`

修改内容：
1. ✅ 增加超时时间：从10秒改为30秒
2. ✅ 添加智能重试机制：每个URL重试2-3次，递增延迟（1秒、2秒、3秒）
3. ✅ 添加备用URL：
   - `http://tianxiazhengyi.net/version.que`（主URL）
   - `https://tianxiazhengyi.net/version.que`（HTTPS备用）
   - `http://www.tianxiazhengyi.net/version.que`（www子域名备用）
4. ✅ 添加详细的日志输出，方便调试
5. ✅ 在所有URL都失败时返回空字符串，由前端处理

**文件**: `src/Renderer/components/MainWindow/index.tsx`

修改内容：
1. ✅ 改进版本获取逻辑，添加 isMounted 检查防止内存泄漏
2. ✅ 当远程版本获取失败或返回空时，使用默认值 `v2.6`
3. ✅ 添加更详细的日志输出
4. ✅ 确保版本检查在组件挂载时立即执行

#### 预期效果
- Remote Version 将在启动后30秒内显示（通过重试机制）
- 即使网络完全失败，也会显示默认值 v2.6
- 用户不会再看到空白的版本号

---

### 2. 开启/关闭MOD经常卡在environment文件夹

#### 问题原因
- `environment` 文件夹包含大量的环境和光照相关文件（DNC文件）
- 该文件夹应该由光照设置（`mdl-handlers.ts`）单独管理
- 在MOD开关时移动 `environment` 文件夹会导致：
  - 移动速度慢（文件数量多）
  - 可能与光照设置功能冲突
  - 文件可能被其他进程锁定

#### 修复方案
**文件**: `src/Renderer/components/MainWindow/index.tsx`

修改内容：
1. ✅ 从 MOD 开关的文件移动列表（`allDirs`）中移除 `environment` 目录
2. ✅ 添加注释说明：`environment` 由光照设置单独管理
3. ✅ 保留其他所有目录的正常移动逻辑

代码变更：
```typescript
// 注意：environment 目录由光照设置单独管理，不在此处移动
const allDirs = [
  'buildings',
  'campaign',
  'cos',
  'doodads',
  // 'environment', // 移除：由光照设置（mdl-handlers.ts）单独管理
  'fonts',
  'patch',
  // ... 其他目录
];
```

#### 预期效果
- MOD 开关速度显著提升
- 不再卡在 environment 文件夹
- 光照设置功能维持独立性，不受影响

### 3. 设置 - 游戏设置 - 地形设置 切换为"原版"时直接卡住

#### 问题原因
- `terrain-handlers.ts` 中的 `ensureEmptyOrSkip` 函数过于保守
- 当检测到目标目录已存在且非空时，直接跳过切换操作
- 这导致：
  - 如果 `QMoff/terrainart` 已存在（上次操作遗留），无法切换到原版
  - 如果 `terrainart` 已存在，无法切换到最新版
  - 用户感觉程序"卡住"，实际上是静默跳过了操作

#### 修复方案
**文件**: `src/Main/ipc/terrain-handlers.ts`

修改内容：
1. ✅ **移除** `ensureEmptyOrSkip` 函数及其过度保守的检查逻辑
2. ✅ **简化** 地形切换流程：
   - 切换到原版（classic/original）：
     - 检查源目录（`terrainart`）是否存在
     - 如果目标目录（`QMoff/terrainart`）已存在，先删除
     - 移动 `terrainart` → `QMoff/terrainart`
   
   - 切换到最新版（latest）：
     - 检查源目录（`QMoff/terrainart`）是否存在
     - 如果目标目录（`terrainart`）已存在，先删除
     - 移动 `QMoff/terrainart` → `terrainart`

3. ✅ 添加详细的控制台日志输出：
   - 当前模式
   - 源/目标路径
   - 目录是否存在
   - 移动操作进度

4. ✅ 使用 `fs.move` 的 `{ overwrite: true }` 选项确保覆盖

#### 预期效果
- 地形切换不再卡住
- 即使目标目录已存在，也能正常切换
- 通过日志可以清楚看到切换过程
- 切换操作更加可靠

## 后续建议

### 1. Environment 目录管理
虽然我们从MOD开关中移除了 `environment`，但需要确保：
- 光照设置功能（`mdl-handlers.ts`）能正确管理 environment 目录
- 当MOD完全关闭时，environment 应该怎么处理？（当前不会移动）
  - **建议**：在 `handleModToggle` 中添加特殊处理，当关闭MOD时，调用光照设置API将environment设为standard模式

### 2. 版本获取优化
- 考虑添加版本缓存机制，避免每次启动都请求
- 可以在后台定期检查更新（每小时一次）
- 添加手动刷新版本的按钮

### 3. 地形切换状态同步
- 当前地形切换后，UI高亮状态会通过 `detectTerrainMode` 更新
- 建议添加切换动画或进度提示，让用户知道操作正在进行

### 4. 错误处理增强
- 为文件移动操作添加更详细的错误信息提示
- 考虑添加操作日志文件，方便用户反馈问题

### 5. 性能优化
- 考虑使用 Worker 线程处理大文件移动
- 添加文件移动进度条（基于文件数量或大小）
